# Supported Targets

mipOS supports both host simulator targets and bare-metal embedded targets. The
simulator is useful for development and testing; bare-metal ports demonstrate
how the same kernel contracts map onto real or emulated hardware.

The target model is selected mostly at the BSP boundary. `mipos_bsp.h` chooses
between `MIPOS_TARGET_SIMU`, `MIPOS_TARGET_QEMU_ARM`,
`MIPOS_TARGET_QEMU_VEXPRESS_A9`, `MIPOS_TARGET_STM32`, and `MIPOS_TARGET_STM8`.
Modern CMake builds cover the simulator, QEMU targets, and an optional STM8
SDCC build; historical physical ports remain in the tree as reference
implementations.

## Target status matrix

| Target | CPU/profile | Build path | Current status | Best use |
|---|---|---|---|---|
| Windows simulator x64/x86 | host process | CMake + Visual Studio | Active | kernel tests, examples, lwIP host networking |
| Linux simulator x64/x86 | host process | CMake + GCC/Clang | Active | CI, TAP networking, filesystem and console examples |
| macOS simulator x64 | host process | CMake + Clang | Active | host examples and unit tests |
| macOS ARM64 | host process | CMake + Clang | Partial | build and unit tests; scheduler context switch disabled |
| QEMU `lm3s6965evb` | Cortex-M3 | `MIPOS_TARGET_QEMU_ARM` | Active workhorse | bare-metal console, filesystem, FatFs, lwIP self-tests |
| QEMU `vexpress-a9` | Cortex-A9 | `MIPOS_TARGET_QEMU_VEXPRESS_A9` | Early bring-up | didactic ARMv7-A startup, PL011 UART, root task |
| QEMU `virt` | virtual ARM platform | roadmap | Planned | future CI-friendly virtio block/network target |
| STM8/ST7 family | 8-bit MCU | SDCC optional build, historical Cosmic/Raisonance | Build baseline | legacy portability reference and free-toolchain bring-up |
| STM32/Cortex-M family | Cortex-M | historical/IAR-era port | Historical baseline | physical-board porting reference |

## Host simulator

The simulator runs mipOS as a normal host process. It is the fastest way to
exercise kernel primitives, filesystem examples, console behavior, and optional
lwIP host networking experiments.

Supported host families:

- Windows x86 and x64 with Visual Studio projects generated by CMake.
- Linux x86 and x64 with GCC/Clang.
- macOS x64 with Clang.
- macOS ARM64 for build and unit tests only; scheduler context switching is not
  currently supported there.

The simulator enables the optional modules by default in the modern CMake build:
`ENABLE_MIPOS_FS`, `ENABLE_MIPOS_STDIO`, `ENABLE_MIPOS_CONSOLE`,
`ENABLE_MIPOS_MALLOC`, and `ENABLE_MIPOS_MPOOL`.

## QEMU lm3s6965evb

The `lm3s6965evb` QEMU target models a TI Stellaris LM3S6965 Cortex-M3 board.
It is the current bare-metal ARM workhorse target.

Current firmware coverage:

- hello-world tick demo;
- interactive mipOS console;
- RAM-backed tiny filesystem demo;
- FatFs demo over QEMU semihosting;
- lwIP network console with an in-memory Ethernet peer;
- lwIP ARP/ICMP self-test firmware.

This target is the best place to validate kernel contracts under a real
bare-metal toolchain before investing in a physical board port.

## QEMU vexpress-a9

The `vexpress-a9` target models a historical ARM Versatile Express Cortex-A9
board. It is useful as a didactic ARMv7-A bring-up target because it exposes a
classic fixed-MMIO board shape.

Current status:

- startup and vector table;
- ARM mode stack setup;
- PL011 UART output;
- critical-section masking through CPSR;
- mipOS root task smoke boot.

Next steps are GIC/timer support, PL181 SD, and LAN9118 Ethernet. That path is
educational: each device can be added one layer at a time.

## QEMU virt roadmap

The QEMU `virt` machine is planned as the future functional and CI-oriented ARM
target. It should eventually use:

- PL011 for early console;
- ARM generic timer and GIC;
- virtio-mmio block device for filesystem tests;
- virtio-mmio network device for lwIP tests;
- optional device-tree parsing after fixed bring-up is stable.

The difference from `vexpress-a9` is intentional. `vexpress-a9` is a historical
teaching board; `virt` is a better long-term automation target.


## STM8 SDCC

The STM8 port now has an optional SDCC build path selected with
`MIPOS_TARGET_STM8_SDCC=ON`. It builds the `examples/stm8` hello-world firmware
with `sdcc -mstm8` and produces an Intel HEX image. The helper scripts can also
start uCsim's `ucsim_stm8`/`sstm8` simulator when it is installed.

This is a toolchain and firmware-image baseline, not yet a complete simulated
STM8S board. The next step is to add a narrower uCsim smoke firmware for startup,
cooperative scheduling, and serial I/O.

## Physical board direction

For a new physical board port with persistent storage and an IP terminal, the
most practical first candidate is the STM32H735G-DK Discovery kit. ST lists it
as active and describes Ethernet, a microSD card connector, USART, STLINK-V3E,
HyperRAM, Octo-SPI flash, and STM32CubeH7 examples. That makes it a good fit for
mipOS because the desired feature path is direct:

1. UART/root task.
2. timer tick.
3. serial console.
4. SDMMC plus FatFs through `mipos_diskio`.
5. Ethernet plus lwIP static IP.
6. ICMP ping.
7. TCP terminal on a simple port such as 2323.

Reference: [STM32H735G-DK product page](https://www.st.com/en/evaluation-tools/stm32h735g-dk.html).

A more powerful but heavier second candidate is the NXP i.MX RT1170 EVKB. NXP
lists it as active and documents a 1 GHz Cortex-M7, 400 MHz Cortex-M4, TF socket
for SD card, gigabit Ethernet, 10/100 Ethernet, SDRAM, Octal Flash, QSPI Flash,
NAND, and MCUXpresso tooling. It is attractive when more headroom is needed, but
it brings more porting complexity: cache, MPU, memory controller setup, richer
clocking, and dual-core choices.

Reference: [MIMXRT1170-EVKB product page](https://www.nxp.com/design/design-center/development-boards-and-designs/i-mx-evaluation-and-development-boards/i-mx-rt1170-evaluation-kit%3AMIMXRT1170-EVKB).

## Historical physical targets

The repository also contains historical embedded support for:

- STM8/ST7-class targets with SDCC baseline and Cosmic/Raisonance-era tooling;
- STM32/Cortex-M-era targets with older embedded toolchains;
- IAR Embedded Workbench ARM configurations;
- `ctxm3`, which preserves older Cortex-M3 context-switch support.

These ports are valuable as examples of the portability layer, even when their
original vendor tools are old. They show which parts of mipOS are stable kernel
contracts and which parts belong to board/toolchain glue.

## Choosing a target

- Use the host simulator when developing application logic or unit tests.
- Use QEMU `lm3s6965evb` when validating bare-metal behavior today.
- Use QEMU `vexpress-a9` when studying ARMv7-A bring-up.
- Use QEMU `virt` when implementing future CI-grade block/network device tests.
- Use STM32H735G-DK when starting a real board port aimed at SD + Ethernet + TCP
  terminal.
- Consider i.MX RT1170 EVKB after mipOS has a stronger Cortex-M7/cache/network
  story and needs more performance headroom.
